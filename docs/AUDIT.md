# Аудит path-flow

Этот документ сопоставляет реализацию с предоставленным ТЗ и фиксирует проверяемые результаты. Он не является заключением внешнего аудитора и не обещает прохождения любой неизвестной проверки.

## Основные требования

| Пункт ТЗ | Реализация и способ проверки |
| --- | --- |
| Имя проекта и Go-модуль | `path-flow`, `go.mod`, `main.go` |
| Обязательная структура | `internal/colony/classifier.go`, `classifier_test.go`, `examples/example00.txt` |
| Только стандартные Go-пакеты | `go list -m all` показывает только собственный модуль; нет `require`, `go.sum` и внешних импортов |
| Чтение колонии из аргумента | `main.go`; `TestCLIExamples`, `TestNoTemporaryFilesNeeded` |
| Только точные `##start` и `##end` | `TestPermittedSyntax`, `TestRejectInvalidInput` |
| Неизвестные команды и комментарии | Игнорируются при разборе, сохраняются в исходной части вывода |
| Формат `Lномер-комната`, одна строка на ход | `internal/routing/output.go`; независимая проверка всей выдачи |
| Минимальное число ходов | Поток минимальной стоимости; аргументация в `ALGORITHM.md`; 3294 исчерпывающих малых случая и 250 случайных графов |
| По одному муравью в обычной комнате | Ограничение разделённой вершины + валидатор конечной занятости + проверка свободной комнаты слева направо |
| Тоннель не более раза за ход | Ограничение потока; специальный тест прямого тоннеля и проверка неориентированного ключа тоннеля |
| Муравей движется не более раза за ход | Арифметика конвейера; независимый replay validator |
| Все достигают выхода | Проверяется для каждого сгенерированного расписания |
| Нет пути, петли, повторы, неверные координаты | Подробные ошибки `ERROR: invalid data format, ...`, ненулевой exit code |
| Повторяемость результата | `TestDeterminism`, стабильные правила выбора путей |
| 100/1000 муравьёв за лимит времени | `TestLargeColonies`, `BenchmarkLarge1000`; фактические числа ниже |
| Профиль перед движениями | `TestTopologyOutput`; комментарии `# Colony profile:` и `# Ant load:` |
| Sparse / connected / dense | `TestTopologyBoundaries`, готовые граничные примеры |
| Отдельно тестируемая дробь | `ConnectivityRatio`, `LoadRatio`; тесты на ноль, отрицательные аргументы и границы |
| Обработка штатных отказов | Ошибки открытия/чтения/записи, отмена контекста, повреждённые записи, ограничения ресурсов |

## Бонусы

| Бонус | Результат |
| --- | --- |
| Визуализатор | Отдельная команда `cmd/visualizer`, конвейер из ТЗ поддерживается |
| Движущиеся муравьи | Интерполяция между комнатами; Play, Pause, Step, Reset, скорость и шкала времени |
| 3D | Трёхмерные координаты, вращаемая камера, перспектива, глубина и сортировка объектов; отдельный 2D-режим |
| Более точные ошибки | Причина и номер строки для ошибок формата |
| Нагрузка light / moderate / heavy | Реализовано и протестировано; `9/6` корректно даёт `moderate` |
| Границы 1.2 и 2.0 | Прямые unit tests и исполняемые примеры |
| Качество и творческий подход | Независимый валидатор, исчерпывающий oracle, fuzzing, офлайн-визуализация, личная тема Ghost of Astana, учебная документация |

## Фактически выполненные проверки

Локальная среда: **macOS, Apple M3, darwin/arm64, Go 1.27.1**. Дата: **30 сентября 2026 года**.

- `go test ./...` — успешно.
- `go test -race ./...` — успешно, гонки данных не обнаружены.
- `go vet ./...` — успешно.
- `gofmt` — исходники отформатированы.
- `go list -m all` — только собственный модуль.
- Сборка обоих исполняемых файлов — успешно.
- Примеры ТЗ `example00`, `example01`, `example02` — соответственно **4, 5, 3 хода**, с независимой проверкой движений.
- Именной пример `ghost-of-astana.txt` — **24 муравья, 11 комнат, 17 тоннелей, 11 ходов**.
- Границы классификаторов и ratio helpers — **100% покрытия** пакета `internal/colony`.
- Первый fuzz-прогон парсера: **578 421 запуск**, 12 секунд заданного fuzz-времени, без найденных сбоев.
- Первый fuzz-прогон replay: **919 160 запусков**, 12 секунд заданного fuzz-времени, без найденных сбоев. После перехода на построчное чтение выполнен отдельный повторный прогон: **119 679 запусков**, без сбоев.
- Стресс-сценарии: полный граф из **120 комнат / 7140 тоннелей / 1000 муравьёв**, цепочка из **15 000 комнат**, **10 000 комнат с тупиковыми ветвями** и недостижимым выходом, **1 000 000 муравьёв** через прямой тоннель с потоковым выводом.

Замеры большой колонии: **4962 комнаты, 5000 тоннелей**, 40 независимых маршрутов по 125 тоннелей. Каждая тестовая проверка включает решение, запись и независимую валидацию движений (разбор подготовленного входа вне замера). Три повторения, параллельно выполнялись и другие проверки:

| Муравьёв | Оптимальных ходов | Измеренное время | Лимит ТЗ |
| --- | --- | --- | --- |
| 100 | 127 | 0.058–0.465 с | 90 с |
| 1000 | 149 | 0.090–0.284 с | 150 с |

Отдельный benchmark решения и записи в `io.Discard` для 1000 муравьёв: **0.060–0.118 с/запуск**, около **38.5 MB суммарных выделений** за запуск. Это не пиковая память процесса. Пропускная способность терминала и другого компьютера может отличаться.

Дополнительно проверен **Go 1.22.12** с `CGO_ENABLED=0`. На этой версии Go обычный запуск тестового бинарника HTTP-визуализатора на установленной macOS остановился в системном загрузчике (`missing LC_UUID`); чистая Go-сборка обходит несовместимость. Проект не требует C. Основные проверки и race detector выполнялись на Go 1.27.1. В CI предусмотрены Go 1.22.x и текущая стабильная версия под Linux; файл workflow сам по себе не означает, что удалённый прогон уже выполнен.

## Проверка интерфейса

В локальном браузере проверены:

- начальное состояние: 24 на старте, 0 в колонии, 0 прибывших;
- первый шаг: 21 / 3 / 0 и корректная строка движений;
- переход к последнему ходу: 0 / 0 / 24, статус `COMPLETE`, кнопка шага отключена;
- обратная перемотка и Reset: исходные счётчики восстановлены;
- воспроизведение со скоростью 3× до завершения;
- переключение 2D/3D;
- ширина 390 px: горизонтального переполнения нет;
- отсутствие ошибок и предупреждений JavaScript в проверенной сессии.

Во время проверки выявлена и исправлена ошибка ползунка: обработчик паузы обновлял его значение прежде, чем считывалась новая позиция. Повторная проверка клавишами Home/End и пошаговой перемоткой подтвердила исправление.

## Границы проверок и трактовки ТЗ

Стандартные ошибки обрабатываются без panic; исчерпание ресурсов ОС, физический отказ диска или принудительное завершение процесса не могут быть исключены программой. Защитные лимиты задокументированы в README. Просмотрщик разбирает запись построчно и проверяет число токенов до выделения больших списков.

Совпадающие координаты не запрещены ТЗ и поэтому разрешены. Дефисы в именах тоже не запрещены; неоднозначные тоннели отклоняются явно. Метка `connected` — категория плотности, а не проверка связности. При отсутствии пути программа сообщает ошибку до печати успешного профиля.

Устная часть аудита (личное понимание автором кода, объяснение без подсказок, предсказание результата новой колонии) не автоматизируется. Для неё подготовлен `WALKTHROUGH_RU.md`.

Указанная в ТЗ школьная ссылка на good practices была недоступна из среды проверки. Применены разделение ответственности, понятные имена, обработка ошибок, gofmt и unit tests; ориентир — [публичные good practices 01-Edu](https://github.com/01-edu/public/blob/master/subjects/good-practices/README.md).
