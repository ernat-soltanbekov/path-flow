# path-flow

**Discipline in motion · Ghost of Astana**

Симулятор муравьиной колонии на Go: читает комнаты и тоннели, находит расписание с минимальным числом ходов и проводит всех муравьёв к выходу без столкновений. Включает классификатор топологии, оценку нагрузки и автономный **3D-визуализатор**.

## Быстрый запуск

Нужен **Go 1.22 или новее**. Только стандартная библиотека Go; внешние Go-пакеты, Node.js, npm, CDN и API-ключи для сборки и запуска не нужны.

```sh
git clone https://github.com/ernat-soltanbekov/path-flow.git
cd path-flow
go run . examples/example00.txt
```

Сборка двух исполняемых файлов:

```sh
go build -o path-flow .
go build -o visualizer ./cmd/visualizer
./path-flow examples/ghost-of-astana.txt | ./visualizer -out path-flow.html
```

Откройте `path-flow.html` в браузере. Это полноценный автономный файл: данные, оформление и анимация находятся внутри. Для локального просмотра через HTTP:

```sh
./path-flow examples/ghost-of-astana.txt | ./visualizer -serve 127.0.0.1:8080
```

Откройте адрес, напечатанный визуализатором; `Ctrl+C` завершает сервер. Сервер слушает только loopback-адрес. На Windows используйте имена `path-flow.exe` и `visualizer.exe`.

## Что выдаёт программа

```text
3
##start
s 0 0
##end
t 1 0
s-t

# Colony profile: rooms 2 | tunnels 1 | topology: sparse
# Ant load: 3 ants | rooms 2 | load: moderate
L1-t
L2-t
L3-t
```

Сначала печатается исходная колония, затем пустая строка, два комментария-классификатора и движения. Один тоннель пропускает **одного муравья за ход**, даже если напрямую соединяет старт и финиш. Один муравей проходит только один тоннель за ход.

Ошибочный файл не даёт частичного расписания:

```text
ERROR: invalid data format, line 7: self-link on room "entry"
```

Код завершения: `0` — успех или справка; `1` — ошибка. Ошибки содержимого и открытия файла выводятся в stdout, как в ТЗ. Неверное число аргументов и ошибки записи выводятся в stderr. При повреждении выходного потока уже записанные байты, естественно, отозвать нельзя.

## Правила входного файла

- Первое значимое содержимое — положительное целое число муравьёв.
- Комната: `имя x y`. Координаты — целые числа, включая отрицательные.
- Ровно одна команда `##start` и одна `##end`; каждая относится к следующей комнате. Комментарии между командой и комнатой допустимы.
- Сначала объявляются все комнаты, затем тоннели `имя1-имя2`.
- Комнаты с одинаковыми именами, петли, повторные тоннели в любом направлении и ссылки на неизвестные комнаты отклоняются.
- Имена не начинаются с `L` или `#` и не содержат пробелов или управляющих символов. Поддерживаются Unicode и дефисы: разделитель тоннеля определяется по объявленным именам; неоднозначные записи отклоняются.
- Только точные строки `##start` и `##end` имеют специальное значение. Другие строки, начинающиеся с `#`, игнорируются при разборе и сохраняются в выводе.
- Допускаются пустые строки, CRLF, UTF-8 BOM и отсутствие завершающего перевода строки. Вывод нормализует переводы строк в LF.
- Одинаковые координаты допустимы: положение на рисунке не влияет на поиск пути. Изолированные комнаты допустимы, если от старта до финиша существует путь.

Защитные границы: входной файл **32 MiB**, строка **4096 байт**, имя **256 байт**, до **1 000 000 муравьёв**, **50 000 комнат**, **250 000 тоннелей**. Превышение возвращает объяснимую ошибку. Координаты должны помещаться в `int` платформы. Число ходов и объём stdout зависят от колонии: длинный маршрут для большого числа муравьёв неизбежно даёт большой вывод.

## Как устроено решение

Представьте несколько коридоров, в каждый из которых раз в ход входит один человек. В длинном коридоре первый человек приходит позже, но затем люди выходят по одному за ход. Нельзя просто выбрать кратчайший коридор и удалить его комнаты: иногда выгоднее изменить этот маршрут и открыть два независимых коридора.

Маршрутизатор использует **поток минимальной стоимости с обратными рёбрами**. Он проверяет полезное количество параллельных путей и распределяет муравьёв по их пропускной способности. Поиск выполняется алгоритмом Дейкстры с потенциалами; перебора всех путей в рабочем алгоритме нет. План хранит пути и количество муравьёв на них, а движения выводятся постепенно.

Подробная аргументация оптимальности, формулы и пример перераспределения — в [docs/ALGORITHM.md](docs/ALGORITHM.md). Объяснения для самостоятельного разбора перед аудитом — в [docs/WALKTHROUGH_RU.md](docs/WALKTHROUGH_RU.md).

## Классификаторы

Логика находится в `internal/colony/classifier.go` и тестируется отдельно.

| Показатель | Диапазон | Результат |
| --- | --- | --- |
| тоннели / комнаты | `< 1.2` | `sparse` |
| тоннели / комнаты | `1.2 … 2.0`, обе границы включены | `connected` |
| тоннели / комнаты | `> 2.0` | `dense` |
| муравьи / комнаты | `< 1` | `light` |
| муравьи / комнаты | `1 … 3`, обе границы включены | `moderate` |
| муравьи / комнаты | `> 3` | `heavy` |

Это классификация по правилам, а не машинное обучение. Метка `connected` обозначает **диапазон плотности**, а не результат проверки связности графа. Все объявленные комнаты и уникальные тоннели учитываются. Например, `9 / 6 = 1.5` даёт нагрузку `moderate`, несмотря на опечатку `heavy` в иллюстрации ТЗ. Для нулевого/отрицательного количества комнат публичные helpers возвращают `0`, без деления на ноль; парсер не допускает такую колонию в решатель.

## Визуализатор

- Трёхмерная перспективная проекция: вращение мышью/пальцем, масштаб колесом, отдельный вид сверху.
- Пауза, пошаговое воспроизведение, перемотка, скорость `0.25× … 3×`, подписи комнат.
- Клавиши: `Space` — пауза, `→` — шаг, `R` — сначала. Стандартные клавиши диапазона работают при фокусе на ползунке.
- Счётчики ожидающих, находящихся в колонии и прибывших; журнал движений и текстовое объявление хода для screen reader.
- Координаты входного файла задают плоскость X/Z. Высота комнаты отображает число её связей. Совпадающие координаты слегка раздвигаются только на рисунке.
- Воспроизведение начинается по нажатию Play, без принудительной анимации при открытии.
- Перед экспортом **независимый валидатор** проверяет каждый переход, занятость комнат, однократное использование тоннелей и прибытие всех муравьёв.
- Имена комнат безопасно кодируются в JSON и выводятся как текст; внешние скрипты и сетевые запросы не используются.

Визуализатор принимает до **64 MiB** текста, до **32 MiB** в одной строке и **1 000 000 движений**. Для крупных графов рисует обзор: до 1600 обычных комнат плюс старт/финиш, до 6000 тоннелей и до 2000 движущихся/ожидающих внутри колонии маркеров за кадр. Полное расписание и точные счётчики сохраняются. Журнал показывает первые 120 движений выбранного хода с указанием общего числа. Эти ограничения касаются только удобства просмотра; CLI выдаёт полное расписание.

## Проверка

```sh
go test ./...
go test -race ./...
go vet ./...
go test -cover ./...
go test ./internal/routing -run TestLargeColonies -v
go test ./internal/routing -run '^$' -bench BenchmarkLarge1000 -benchmem
go test ./internal/farm -run '^$' -fuzz FuzzParse -fuzztime 10s -parallel 2
go test ./internal/replay -run '^$' -fuzz FuzzReplay -fuzztime 10s -parallel 2
```

Для `-race` нужен поддерживаемый Go race detector и C toolchain. Обычные сборка и тесты этого не требуют. На новых версиях macOS для старого Go 1.22 может понадобиться `CGO_ENABLED=0 go test ./...` из-за совместимости системного загрузчика; проект не использует C. На Go 1.27.1 обычный запуск и `-race` проверены без этого обхода.

Тесты включают полный перебор **3294 комбинаций графа и числа муравьёв** (все простые графы с 2–5 комнатами, 1–3 муравья), ещё **250 случайных графов** с фиксированным seed, ловушку для жадного поиска, прямой тоннель, повреждённые входные данные, отмену выполнения, ошибки записи, безопасное встраивание имён в HTML и нагрузочные колонии с 100/1000 муравьями.

Сопоставление с пунктами аудита и фактические результаты — в [docs/AUDIT.md](docs/AUDIT.md). Автоматические проверки не заменяют устное объяснение проекта автором: для этого есть подробный разбор кода и вопросы для практики.

## Структура

```text
path-flow/
├── go.mod
├── main.go                   # Аргументы, чтение, ошибки, запуск
├── main_test.go
├── cmd/visualizer/            # Отдельная команда экспорта и локальный HTTP
├── internal/
│   ├── colony/               # Топология и нагрузка + unit tests
│   ├── farm/                 # Строгий парсер, граф, ограничения
│   ├── routing/              # Поток, расписание, потоковый вывод
│   ├── replay/               # Независимая проверка движений
│   └── viewer/               # Встроенный HTML/Canvas 3D
├── examples/                 # Примеры ТЗ, личная тема, границы, ошибки
├── docs/                     # Алгоритм, аудит, учебный разбор
└── .github/workflows/        # Автоматическая проверка сборки и тестов
```

Сборка воспроизводима без сторонних Go-модулей. Одинаковый входной файл даёт одинаковый вывод. Алгоритмические комментарии объясняют причины решений; подробности для начинающих вынесены в документацию.
